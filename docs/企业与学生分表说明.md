# 企业与学生分表

企业账号保存在 MySQL 的 `publisher_user`，学生账号保存在 `student_user`。这两张表各自保存手机号密文、密码哈希、个人资料和实名认证状态。

| 用途 | 文件（相对于项目根目录） |
| --- | --- |
| 企业实体 | `backend/src/main/java/cn/campus/jobs/user/PublisherUser.java` |
| 学生实体 | `backend/src/main/java/cn/campus/jobs/user/StudentUser.java` |
| 企业数据库操作 | `backend/src/main/java/cn/campus/jobs/user/PublisherUserRepository.java` |
| 学生数据库操作 | `backend/src/main/java/cn/campus/jobs/user/StudentUserRepository.java` |
| 企业页面：登录、认证、工作台、发布岗位 | `frontend/src/pages/publisher/PublisherApp.vue` |
| 学生页面：登录、认证、发现兼职、领取岗位 | `frontend/src/pages/student/StudentApp.vue` |
| 两端共用的请求与会话逻辑 | `frontend/src/composables/usePortal.js` |

`AccountFields` 是共用字段的 Java 值对象，不对应共用用户表。`UserRepository` 负责根据身份调用两个独立的 Repository。`account_identity` 只保存全局用户 ID 和角色，为会话、头像、审核历史和钱包提供统一关联；不存放密码、手机号或个人资料。岗位外键直接关联企业表，领取记录外键直接关联学生表。

`App.vue` 只选择入口：`/publisher` 打开企业界面，`/student` 打开学生界面。两端可以分别修改页面布局；头像、个人资料编辑、主页、历史和钱包中的通用组件继续复用。两端使用同一个登录 Cookie，点击切换身份时先退出当前账号，再进入另一个端口的登录页面。

## 已有数据库升级

重新启动 IDEA 中的后端 Application 后，Flyway 自动执行 `backend/src/main/java/db/migration/V4__Split_publisher_and_student_users.java`。无需手动运行建表语句，也不要修改已执行的 V1–V3 脚本。

迁移按角色复制旧账号，保持用户 ID、密码哈希、敏感字段密文、资料和时间不变；岗位、接取记录、头像、钱包及流水继续关联原用户 ID。旧表改名为 `app_user_legacy_v3` 留作迁移存档，应用此后不再读写它。存档不会同步新注册或编辑的数据，查看当前用户请使用两张新表。

```sql
SELECT id, organization, nickname, verification_status, can_publish FROM publisher_user;
SELECT id, school, nickname, grade, major, verification_status, can_accept FROM student_user;
```

已有账号密码保持不变。继续使用原来的数据库配置与加密密钥，不要更换 `APP_ENCRYPTION_KEY` 或 `APP_LOOKUP_KEY`，否则旧数据无法正常解密或登录。升级后刷新前端页面即可。
