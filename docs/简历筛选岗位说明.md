# 简历筛选岗位

企业发布岗位时可选择“直接参加”或“简历筛选”。原有岗位默认为直接参加。

简历筛选岗位的学生在详情页填写在线简历（最多 8000 字）并提交，报名状态为“待筛选”。企业在岗位详情或发布记录中打开“查看简历 / 筛选”，查看简历后选择录取或不录取。学生会收到消息通知，并可在岗位详情和报名记录中查看结果。仅录取后的学生可以参加和结算。

岗位列表、详情和企业报名页显示已报名人数、需要人数、已录取人数。已报名人数包含待筛选、已录取、未录取的报名，不包含已退出的报名。待筛选不占名额，报名人数可超过需要人数；录取人数不得超过需要人数，录取名额满后停止新报名。录取或不录取的结果不能重复修改；学生退出后不能再次报名。

开工前学生可撤回待筛选报名或退出已录取岗位。企业取消岗位会通知待筛选及已录取学生。已取消或已开始的岗位不允许继续筛选。

简历按报名记录保存并加密存储，仅本岗位发布者能从报名管理接口读取，不在岗位列表、公共详情或个人主页公开。当前简历为在线文本填写。

## 接口

- `POST /api/jobs`：新增可选字段 `recruitmentMode`，值为 `DIRECT` 或 `SCREENING`；省略时使用 `DIRECT`。
- `POST /api/jobs/{id}/apply`：筛选岗位需提交 `{ "resume": "在线简历内容" }`，直接参加岗位可继续使用无请求体或空对象。
- `GET /api/jobs`、`GET /api/jobs/{id}`、`GET /api/companies/{id}/jobs`：包含 `recruitment_mode`、`applications`（已报名）、`required_count`（需要）、`accepted_count`（已录取）、`remaining`（剩余录取名额）。自己的报名状态由 `application_status` 返回。
- `GET /api/jobs/{id}/applicants`：仅发布者可调用，返回报名状态、简历和人数统计。
- `POST /api/jobs/{id}/applications/{applicationId}/decision`：仅已认证且具备发布权限的岗位发布者可调用，请求体为 `{ "accepted": true }`（录取）或 `{ "accepted": false }`（不录取）。

数据库通过 Flyway `V9__resume_screening.sql` 增量升级，已有岗位及报名记录保持原来的直接参加行为。后端重启时自动执行升级。
