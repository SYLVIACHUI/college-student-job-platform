# 站内消息通知

企业端和学生端顶部新增「消息」按钮，显示未读数量。消息中心支持分页（每页20条）、只看未读、单条标为已读、全部已读和业务跳转。页面可见且已登录时约每15秒刷新；消息保存于数据库，离线后再次登录仍可查看。此版本没有短信、操作系统推送或 WebSocket。

## 触发规则

| 事件 | 接收者 | 跳转 |
| --- | --- | --- |
| 实名认证审核通过或驳回 | 被审核的企业/学生账号 | 实名认证页 |
| 学生成功报名 | 岗位发布企业 | 岗位详情 |
| 学生成功退出 | 岗位发布企业 | 岗位详情 |
| 企业发放模拟兼职费成功 | 收款学生 | 钱包与流水 |
| 企业取消活动 | 当时仍处于报名状态的学生 | 已取消岗位详情 |

消息只包含公开昵称、岗位名称、模拟报酬金额、取消原因等必要业务信息，不包含证件、姓名、学号、手机号。旧业务记录不会自动补发消息；部署后发生的新操作才触发通知。开发模拟审核同样会产生通知，测试数据只在隔离的内存库生成。

## 退出与活动取消

- 学生在岗位详情点击「退出兼职」，确认后将报名状态改为 `WITHDRAWN`，释放名额，保留报名历史。本版退出后不能再次报名同一岗位。
- 企业在自己的岗位详情点击「取消活动」，填写最多300字的原因并确认，岗位状态变为 `CANCELLED`；只通知仍报名的学生，不通知已退出者。
- 退出、取消都仅允许在开始时间之前；未设置开始时间的旧岗位暂不支持。
- 已结算的报名不能退出；任何学生已结算的活动不能直接取消。真实退款、开工后违约处理尚未实现。
- 已退出报名或已取消活动不能继续结算。已取消活动不能新增报名，不在学生发现列表和企业目前招聘列表展示，但历史记录、详情及通知仍保留。
- 重复退出或重复取消不重复发通知。重复结算沿用原有请求幂等规则，不重复扣款、入账或发通知。

## 数据库设计

迁移：`backend/src/main/resources/db/common-migration/V8__notifications_and_cancellations.sql`。

新增 `notification` 表：

| 字段 | 用途 |
| --- | --- |
| id | 消息UUID |
| recipient_id | 接收人，关联 account_identity，兼容企业和学生分表 |
| event_key | 业务事件唯一键，与接收人组成唯一约束 |
| kind | 审核通过/驳回、报名、退出、收入、取消类型 |
| title / content | 消息标题与正文快照 |
| target_type / target_id | 跳转类型 VERIFY、JOB、WALLET 与岗位ID |
| read_at | NULL代表未读，已读后保存时间 |
| created_at | 生成时间，按时间、ID倒序分页 |

增加接收人+时间索引及接收人+已读时间索引。`job` 增加状态、取消原因和取消时间；`job_application` 增加状态和退出时间，旧记录默认仍有效。

## 一致性与权限

通知直接参与业务数据库事务。`NotificationService.send` 要求调用方已有事务；业务失败时通知一起回滚。采用审核申请ID、报名ID、结算操作ID、岗位ID构成事件键，配合业务状态检查和数据库唯一约束防止重复消息。

报名、退出、取消、结算统一先锁岗位行；退出和结算再锁报名行，结算最后按用户ID顺序锁钱包。取消与结算并发时不能同时成功。站内消息只需数据库持久化，不依赖外部推送服务，因此本版无需消息队列或发送重试任务。

读取与标记已读均从登录会话取得当前用户，不接受客户端指定接收人。所有查询、更新都限定接收人；不存在或不属于当前用户的消息返回404。

## 接口

| 方法 | 地址 | 说明 |
| --- | --- | --- |
| GET | /api/notifications?page=0&unreadOnly=false | 当前用户消息列表 |
| GET | /api/notifications/unread-count | 当前用户未读数量 |
| POST | /api/notifications/{id}/read | 标记单条已读 |
| POST | /api/notifications/read-all | 将操作执行时的当前用户未读消息标为已读 |
| POST | /api/jobs/{id}/withdraw | 学生退出报名 |
| POST | /api/jobs/{id}/cancel | 企业取消活动，JSON正文包含 reason |

变更接口沿用现有会话Cookie与 `X-Requested-With: campus-web` 校验。

## 使用与验证

1. 在 IDEA 重启后端，沿用原 MySQL、Redis 和加密密钥配置。Flyway 自动执行 V8，不需要手动建表或删除旧数据。
2. 前端已构建。如果之后继续修改源码，在项目根目录执行 `./scripts/frontend-nginx.ps1 -Action reload`；位于 frontend 目录则执行 `../scripts/frontend-nginx.ps1 -Action reload`。
3. 刷新网页并登录，点击顶部「消息」。新审核、报名、退出、发放模拟报酬或取消活动后查看对应账号的通知。

测试覆盖：审核结果、本人消息隔离、已读幂等、未读筛选、报名与退出通知、名额释放、取消通知受众、失败交易不产生到账通知、重复支付只通知一次、事务回滚、并发取消与结算互斥。前端经过构建、门户渲染测试和手机宽度下的浏览器验证。
